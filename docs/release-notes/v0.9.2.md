# v0.9.2

Bugfix. Non-breaking; no CRD/API change, no connection-secret changes.

## Fixed

- **NAT on an existing Router looped forever with `IP not found` (timeweb-infra#135).**
  Declaring `natFloatingIP` on a network attachment of an already-created Router never
  converged: the upstream NAT operation only accepts addresses the router already owns, and
  only the create path attached them. The update path now binds the referenced floating IP to
  the router first (`resource_type: router` — undocumented but live-verified upstream bind
  target) and enables NAT once ownership is observed:

  ```yaml
  # adding NAT egress to an attachment of a LIVE router now just works
  networks:
    - networkRef: {name: production}
      dhcp: true
      natFloatingIP:
        ref: {name: production-egress}
  ```

- The provider never unbinds a floating IP held by another resource: the Router reports
  `Ready=False NATIPUnavailable` naming the holder and converges by itself once the address
  is freed. One blocked attachment no longer stalls convergence of the router's other
  attachments.
- Removing `natFloatingIP` disables NAT; the address stays attached to the router
  (declarative release is planned for a future release).

See [docs/routers.md](https://github.com/lebedevdsl/crossplane-provider-timeweb/blob/v0.9.2/docs/routers.md)
for the NAT behavior reference.
