# v0.11.1

Bugfix. Non-breaking; no CRD/API change.

## Fixed

- **Duplicate creates on a stomped external-name (incident 2026-07-25).** A
  GitOps-pinned stale `crossplane.io/external-name` (Argo selfHeal reverting
  the provider-written value) made each sync cycle mint a new node group —
  three billable groups from one manifest. The provider now detects the
  contradiction — external-name pointing at a missing upstream object while
  `status.atProvider.upstreamID` remembers a different live one — and parks
  the resource with `Ready=False ExternalNameConflict` naming both ids and
  the remedies, instead of creating. Genuine out-of-band deletions (same id
  on both sides) still recreate exactly as before.
- **Lost create results could duplicate node pools.** A create whose result
  never lands (timeout, provider restart mid-create, error-yet-created
  response) was retried as a fresh POST. Retried creates now first match the
  parent cluster's groups against the full declared identity: one match is
  adopted, several surface `Synced=False AdoptionAmbiguous` (adopt explicitly
  by external-name, remove the extras) — never a guess, never another
  duplicate. Clean creates are unchanged.

## Also

- New docs: `crossplane.io/external-name` is provider-owned — never render it
  from git; ArgoCD `ignoreDifferences` example; runbook for the
  "cannot determine creation result" wedge (recovery cannot duplicate
  post-fix).
