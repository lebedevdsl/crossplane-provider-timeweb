# v0.14.0

Bugfix. Non-breaking; additive CRD enum value, no connection-secret changes.

## Fixed

- **`S3Bucket` could not order any sellable tier (timeweb-infra#255).** Timeweb rotated
  the S3 catalog on 2026-10-13: a third class `standard` (the panel's "Standard") replaced
  the old `hot` tier, `hot` now means "Premium" and answers `409 Storage class hot is sold
  out`, `cold` exists only at 1 GB. The provider's enum knew `hot`/`cold` only, so every
  create looped on the sold-out tier. `storageClass` now accepts `standard`:

  ```yaml
  spec:
    forProvider:
      storageClass: standard   # Standard (recommended); hot = Premium; cold = 1 GB only
      initialSizeGB: 10
  ```

- **Day-2 edits no longer re-tier the bucket.** Editing `description`, `type` or `projectID`
  used to re-resolve and send `preset_id` on every update — on a bucket the vendor had moved
  to `standard` that meant a silent move to Premium (sold out today, a paid move later). A
  tier is now sent only for a resize within the same class.
- **Declared class ≠ upstream class refuses the update** (`Synced=False`, Warning Event
  `StorageClassMismatch`, nothing sent). Align `spec.forProvider.storageClass` to the
  upstream value; cross-class moves on an existing bucket are not supported.

## Added

- **`StorageClassDrift` condition** on `S3Bucket`: `True/UpstreamReclassified` when the
  vendor reports a different class than declared, `False/Aligned` once the spec matches
  again. `Ready`/`Synced` are unaffected; nothing is repaired automatically.
- Catalog hint on a missing size/class combination lists `<GB>/<location>/<class>`.

## Upgrade note

Buckets bought as `hot` before 2026-09 were moved upstream to `standard`; after the upgrade
they show `StorageClassDrift=True`. Set their `storageClass: standard` — no request is sent,
the condition clears. See [`docs/s3bucket.md`](../s3bucket.md).
