# v0.10.0

Router peering + cluster network ranges. Non-breaking — all new fields optional
and additive; existing manifests behave identically.

## Router: declarative static routes

```yaml
    staticRoutes:
      - subnet: 10.12.0.0/24
        nexthop: 10.13.0.3            # literal next-hop
      - subnet: 10.14.0.0/24
        via:                          # nexthop = the neighbor router's
          routerRef: {name: shared}   # observed gateway in the common network
          networkRef: {name: transit}
```

- Set semantics keyed by subnet; out-of-band panel deletions are repaired,
  removed entries deleted, changed nexthops replaced. Mirrored at
  `status.atProvider.staticRoutes`.
- The `via` form resolves the platform-assigned gateway you cannot know in
  git; it waits until the neighbor Router is Ready, then converges.

## Router: multi-router networks & NAT release

- A Network attached to several Routers (the official peering arrangement) is
  fully supported — each Router CR converges only its own attachment.
- Removing (or moving) `natFloatingIP` now also unbinds the address from the
  router: it is immediately reusable, no manual unbind. Skipped with an event
  when the address is still declared elsewhere on the router or a DNAT rule
  forwards it; addresses attached out-of-band are never touched.

## KubernetesCluster: internal ranges

```yaml
    clusterNetworkCIDR:        # create-only; omitted => platform defaults
      podsNetwork: 10.100.0.0/16
      servicesNetwork: 10.101.0.0/16
```
