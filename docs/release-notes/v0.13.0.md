# v0.13.0

Scale-to-zero worker pools: `KubernetesClusterNodepool` now accepts
`autoscaling.minSize: 0` (previous floor: 2) — an idle pool is drained to zero
nodes and zero cost, and grows back when targeted pods appear.

```yaml
apiVersion: kubernetes.m.timeweb.crossplane.io/v1alpha1
kind: KubernetesClusterNodepool
spec:
  forProvider:
    name: ci
    clusterRef: {name: main}
    resources: {cpu: 4, ramGB: 8, diskGB: 60}
    nodeCount: 1                                      # ignored while autoscaling
    autoscaling: {enabled: true, minSize: 0, maxSize: 3}
    labels: {pool: ci}                                # pods target the pool by these
```

- A converged pool at zero nodes reports `Ready=True` — that is its steady
  state, not an error.
- `maxSize` floor is now 1 (`{minSize: 0, maxSize: 1}` = single-node burst
  pool); `maxSize >= minSize` still enforced.
- New `status.atProvider.autoscaling` mirrors the flag and bounds the upstream
  group actually reports.

⚠️ Scale-to-zero has upstream prerequisites the provider does not check: the
cluster needs **≥ 2 permanently active nodes in other pools**, and pods must
target the pool via `nodeSelector`/`nodeAffinity` to wake it. Details and drain
blockers: [docs/kubernetes.md](https://github.com/lebedevdsl/crossplane-provider-timeweb/blob/v0.13.0/docs/kubernetes.md).
