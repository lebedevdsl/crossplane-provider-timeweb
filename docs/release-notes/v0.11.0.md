# v0.11.0

KubernetesCluster ↔ Router integration. Non-breaking — new fields optional and
additive; existing clusters behave identically.

## Added

```yaml
# KubernetesCluster
    networkRef: {name: app-net}
    routerRef:  {name: edge}    # NEW — required for private worker pools
```

- **`routerRef` / `routerID`** declare the Router a cluster integrates with —
  the platform's «Интеграция с роутерами», which is never automatic and was
  previously panel-only. The provider integrates once the cluster exists and
  the router NATs the cluster network, repairs panel-side detaches, moves the
  integration when the ref changes, and detaches when it is removed. Day-2 and
  fully mutable.
- `status.atProvider.routerIntegrated` mirrors the linkage (read back through
  the router's `parentServices`); `Ready=False RouterNATRequired` names the
  wait state while the router side is still converging.

## Also

- A private (`publicIP: false`) nodepool rejected for a missing integration
  now reports the one-line remedy (set `routerRef`) instead of a raw
  `router_required_for_worker_groups_without_public_ip` retry loop —
  recreating the cluster is never required.

See [docs/kubernetes.md](https://github.com/lebedevdsl/crossplane-provider-timeweb/blob/v0.11.0/docs/kubernetes.md)
for the private-cluster arrangement.
