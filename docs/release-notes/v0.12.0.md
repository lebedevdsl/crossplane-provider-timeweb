# v0.12.0

Hardening and hygiene from a three-way audit (code quality, security, operator
usability). Non-breaking except the admission change called out below.

## ⚠️ New admission rejections

Create-only fields that were previously accepted-and-ignored now fail at
`kubectl apply`: Server `sshKeyRefs`/`sshKeyIDs`/`networkRef`/`networkID`/
`projectRef`/`projectID`, and KubernetesCluster `networkRef`/`networkID`/
`projectRef`/`projectID`. Manifests carrying such an edit — including drift
already sitting in git — will be rejected with the field named and the remedy
(revert, or delete and recreate). Previously the edit silently did nothing
while reporting `Synced=True`.

`clusterSelector` no longer satisfies the required parent reference on
Nodepool/Addon (it is not implemented in v0.x): use `clusterRef` or `clusterID`.

## Fixed

- Unfunded S3Bucket, S3User and Addon resources reported endless `Creating`;
  they now surface `PaymentRequired` like every other kind.
- The API token could be re-sent across an HTTP redirect to another host; it
  is now bound to the API host and cross-host redirects are refused.
- Errors from secret-bearing writes (CDN certificate upload, config PATCHes)
  could echo payload fragments into conditions and Events; PEM blocks and
  secret-named values are scrubbed.

## Added

- **`MESSAGE` column on every kind** — `kubectl get` now shows the Ready
  condition's message, so a blocked resource is distinguishable from one that
  is merely provisioning.
- **[docs/troubleshooting.md](https://github.com/lebedevdsl/crossplane-provider-timeweb/blob/v0.12.0/docs/troubleshooting.md)** — single entry point, linked from the README and every guide.
- **[docs/gitops.md](https://github.com/lebedevdsl/crossplane-provider-timeweb/blob/v0.12.0/docs/gitops.md)** + `examples/argocd/application.yaml` — external-name ownership and the required `ignoreDifferences` stanza.
- **[docs/upgrading.md](https://github.com/lebedevdsl/crossplane-provider-timeweb/blob/v0.12.0/docs/upgrading.md)** and `make preflight` — read-only, production-safe post-upgrade check.
- `examples/private-cluster.yaml` — the whole private-cluster arrangement in one file.
- Releases now carry an SBOM attestation; `SECURITY.md` documents identity-constrained `cosign verify`.

## Note for container-registry users

The registry pull Secret's password is whatever token its ProviderConfig
holds. [docs/containerregistry.md](https://github.com/lebedevdsl/crossplane-provider-timeweb/blob/v0.12.0/docs/containerregistry.md)
now leads with the recommended setup: a registry-scoped token in a dedicated
ProviderConfig, so the Secret cannot carry account-wide rights.
