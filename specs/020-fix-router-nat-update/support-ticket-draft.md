# Черновик обращения в поддержку Timeweb Cloud (feature 020, обновлён 2026-07-25)

Тема: Роутеры/K8s — недокументированные поля API, рассинхрон состояния после
attach сети к живому роутеру, утечка зарезервированных IP

Здравствуйте!

Наблюдения по публичному API (api.timeweb.cloud), проверены 2026-07-24/25.

## 1. `POST /api/v1/floating-ips/{id}/bind` принимает `resource_type: "router"`, но это не документировано

- В OpenAPI-спецификации enum `resource_type` = `server|balancer|database|network`.
- Фактически `{"resource_type": "router", "resource_id": "<UUID роутера>"}`
  возвращает 204 и корректно привязывает IP к роутеру (после этого работает
  `PATCH /routers/{id}/networks/{net}/nat`).
- Это единственный способ добавить IP существующему роутеру через API:
  `ips[]` есть только в теле создания роутера, `POST /routers/{id}/ips` не
  существует, `PATCH /routers/{id}` несёт только name/comment.

Просьба: задокументировать значение `router` (и строковый UUID в `resource_id`).

## 2. Сеть, привязанная к живому роутеру, не принимается k8s-сервисом под приватные группы нод — рассинхрон снапшота атрибутов

- Сеть привязана к существующему роутеру, NAT и DHCP фактически включены
  (видны в GET роутера и в панели).
- Создание группы нод без публичных IP (в т.ч. запросом, идентичным панельному,
  с `virtual_router_id`) стабильно отвечает цепочкой
  `router_required_for_worker_groups_without_public_ip` →
  `router_must_have_nat_ip_for_cluster_network` →
  `router_must_have_dhcp_enabled…` — переключение атрибута сдвигает цепочку на
  шаг, но не закрывает её. response_id: e98f2f7b-9aef-4281-ad8c-f723de32717d,
  490867cd…, f76e5d1b….
- Для сетей, прописанных в ТЕЛЕ создания роутера, всё работает.

Просьба: починить пересчёт состояния сети для k8s-проверок после attach к
живому роутеру (или задокументировать, что поддерживается только wiring через
тело создания роутера).

## 3. `virtual_router_id` в создании группы нод не документирован

Панель отправляет `virtual_router_id: "<router-uuid>"` в
`POST /k8s/clusters/{id}/groups` для групп без публичных IP — поля нет в
OpenAPI. Просьба задокументировать (для IaC-инструментов это ключевое поле).

## 4. Утечка зарезервированных адресов после detach сети

После отвязки сети от роутера её per-attachment адреса остались занятыми
(busy 10.12.0.4 и 10.12.0.9 в нашем случае) без владельца. Просьба почистить и
починить освобождение.

## 5. `GET /routers/{id}/static-routes/available` всегда пуст

Даже при наличии валидных nexthop'ов (шлюз соседнего роутера в общей сети).
Просьба уточнить назначение эндпоинта.

Спасибо!
